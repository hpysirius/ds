# 1688「以图搜图」自动化可行性调研

> 调研时间：2026-10-07 ｜ 目标：把「Ozon 商品图 → 1688 找同款」这一步做成自动的
> 方式：反编译 1688 图搜页前端 + 用真实登录态做端到端 curl 实测

---

## 0. 一句话结论

**接口链路能跑通（已实测拿到真实结果），但风控非常严重 —— 同样的请求第二次就被判「非法请求」。**

因此：

- ❌ **不能做**无人值守、批量、稳定可用的全自动
- ✅ **可以做**「人工点一次 → 自动试一次 → 结果给人挑 → 选中后自动回填」的半自动
- ⚠️ 风控是**账号级**的（用的是你真实的 1688 账号），滥用有触发滑块/限制的风险

## 2. 完整链路（已反编译还原）

图搜页入口会重定向到一个 SPA：

```
https://s.1688.com/youyuan/index.htm?tab=imageSearch
      ↓ 302
https://air.1688.com/kapp/1688-search/pc-image-search/?tab=imageSearch
```

前端 bundle（含全部接口逻辑）：

```
https://g.alicdn.com/1688-search/pc-image-search/0.0.28/js/{213,p_index,main,490}.js
```

整体是两步 MTOP 调用，走的是 **同一个** MTOP 接口，靠 `params` 里的字段区分行为：

```
Ozon 商品图 ──base64──▶ [步骤1] imageBase64ToImageId ──▶ imageId
                                                          │
                                                          ▼
                              [步骤2] getOfferList ──▶ 1688 商品列表（标题/价格/offerId/卖家）
                                                          │
                                                          ▼
                        https://detail.1688.com/offer/{offerId}.html
                                                          │
                                                          ▼
                       复用现有 POST /pricing/sourcing/offer 抓取价格+重量 → 回填核价
```

## 3. 接口契约（可直接复用）

### 3.0 通用：MTOP 签名

- **host**：`https://h5api.m.1688.com`
- **path**：`/h5/mtop.relationrecommend.wirelessrecommend.recommend/2.0/`
- **appKey**：`12574478`
- **v**：`2.0`
- 查询参数：`jsv=2.7.2&appKey=&t=<毫秒>&sign=<md5>&api=<api>&v=2.0&type=originaljson&dataType=jsonp&timeout=20000&data=<urlencode(data)>`

**签名**：`sign = md5("{tokenA}&{t毫秒}&{appKey}&{data}")`

**关键坑（必读）**：

1. `tokenA` 来自 cookie `_m_h5_tk` **下划线之前**的部分；需要**先空请求一次**让服务端下发该 cookie。
2. **必须用 cookie jar 保持会话**（`curl -b jar -c jar`）。手动拼 `Cookie:` 头会返回 `FAIL_SYS_TOKEN_EMPTY::令牌为空`。
3. `Referer` 必须带 `https://air.1688.com/`。

### 3.1 步骤 1：上传图片拿 imageId

```json
{
  "appId": "32517",
  "params": "{\"searchScene\":\"imageEx\",\"interfaceName\":\"imageBase64ToImageId\",\"serviceParam.extendParam[imageBase64]\":\"<图片 base64>\",\"subChannel\":\"pc_image_search_image_id\"}"
}
```

**实测响应（成功）**：

```json
{
  "api": "mtop.relationrecommend.wirelessrecommend.recommend",
  "data": { "imageId": "1415108852570976718", "success": true, "result": [] },
  "ret": ["SUCCESS::调用成功"],
  "v": "2.0"
}
```

**坑**：base64 塞在 URL 里会触发 `header field too large`（实测 24KB 失败）。
→ 图片需先压缩，**约 4KB base64 以内**才能发出去（`sips -s format jpeg -s formatOptions low -Z 160`）。

注：前端原实现用 `FileReader.readAsDataURL`，即带 `data:image/*;base64,` 前缀的完整 DataURL；实测纯 base64 也能被接受。

### 3.2 步骤 2：imageId → 商品列表

```json
{
  "appId": "32517",
  "params": "{\"method\":\"getOfferList\",\"searchScene\":\"pcOfferSearch\",\"imageId\":\"<imageId>\",\"beginPage\":1,\"pageSize\":60,\"verticalProductFlag\":\"pcmarket\",\"charset\":\"GBK\"}"
}
```

**实测**：首次调用返回 `code: 200`，`data.data.OFFER` 内含真实商品数据（含 expoArgs / trackInfo 等完整搜索结果结构）。

**其他 params 变体（均已实测失败，勿用）**：

| 变体 | 返回 |
|---|---|
| `searchScene:"imageEx"` + `interfaceName:"getOfferList"` | `code:5401` result is null |
| `searchScene:"imageEx"` + `method:"getOfferList"` | `code:5401` result is null |
| 仅 `searchScene:"imageEx"` + `imageId` | `code:5401` result is null |

## 4. 风控实测（最关键的部分）

对步骤 2 连续发起**完全相同的请求**：

| 次数 | 结果 |
|---|---|
| 第 1 次 | ✅ `code:200`，返回真实 OFFER 搜索结果 |
| 第 2 次（紧接着） | ❌ `FAIL_SYS_ILLEGAL_ACCESS::非法请求` |

这说明服务端有**重放/频率检测**。两次调用之间需要做：重新握手拿 token、放慢节奏、加随机 `pageId`/`pvid`（页面端本来就有 48 位随机 `pageId`）等手段，但**没有任何手段能保证稳定成功**。

这与项目此前调研的结论一致 —— 1688 风控极严，自动化请求（包括以图搜款）几乎必然间歇性触发滑块验证。

## 5. 三个可选方案

### 方案 A｜半自动「点一次，自动找」（推荐）

保持既有边界（**人工触发、单次、有明确 URL**），只把「打开浏览器 + 拖图」替换掉：

1. 商品库/核价页加按钮 **「1688 找同款」**
2. 后端：压缩图 → 步骤 1 → 步骤 2 → 返回 Top N
3. 前端展示候选卡片（图/标题/价格/销量/卖家），**人工点选**
4. 选中的 offerId 拼成 URL → 调现有 `POST /pricing/sourcing/offer` → 回填核价页
5. **失败时明确提示并回落到现在的手动流程**（不阻塞）

优点：不破坏现有流程、有人工兜底、符合既定产品边界。
缺点：仍会间歇失败（需做好失败文案）。

### 方案 B｜deeplink 快跳（零风险，改动最小）

按钮直接用 `window.open` 打开图搜页并**预填图片**（若能），做不到的部分只省「找入口」这一步。

优点：零风控风险。缺点：省的时间有限。

### 方案 C｜全自动（不建议）

后台批量跑。收益最高但会频繁触发风控、污染账号，**明确不建议**。
