# 服务器模式下「1688 找货 → 核价 → 保存」自动化技术方案

> 编写时间：2026-10-09　状态：**待评审**（只出方案，未开工）
> 目标：在 http://ozon.qinxianty.com（云服务器部署）上，完成「1688 找同款 → 抓采购价 → 算定价 → 保存记录」的自动化闭环。

---

## 一、结论先行

**服务器直连 1688 这条路是死的，不是配一下就能解决。** 实测证据：

```
GET  /api/pricing/sourcing/cookie-status   → {"hasCookie":false,"cookieCount":0}
POST /api/pricing/sourcing/offer           → 400
{
  "code": "ALI_RISK", "riskKind": "IP_BAN",
  "message": "1688 把云服务器的机房 IP 段整体拉黑了（cloud_ip_bl），连滑块都不给：
              请改用本机出口或配住宅代理"
}
```

1688 对整个**云机房 IP 段**做了段级封禁（不是封单个 IP、不是限频），因此：

- 换服务器 IP / 重启 / 换 UA / 换 cookie **都没用**；
- 连"手工贴 offer 链接抓价"这种最轻量的请求在线上也是失败的（现存问题，不只是自动化的问题）；
- 只有**本机出口（家庭宽带）**或**住宅代理**能访问 1688。

**因此方案的本质是：把「出网访问 1688」这个动作从服务器挪走，服务器只做编排 + 计算 + 存储。**
而 1688 交互必须在用户本机完成——这也正好绕开了「headless Chrome 图搜返回空」的坑（本机是真实 GUI + 真实登录态 + 家庭 IP）。

**推荐方案：A（云控本机浏览器）做短期落地，D（1688 官方开放 API）做长期正解。**

---

## 二、能力拆解：到底哪一步卡住了

| 步骤 | 现在在哪跑 | 服务器能不能直接做 | 卡点 |
|---|---|---|---|
| ① 取商品主图 | 服务器（从 products.imageUrl 下载 Ozon 图） | ✅ 可以 | 无（Ozon 图不经过 1688） |
| ② 1688 图搜找同款 | 本机 Chrome（CDP） | ❌ **不行** | 服务器 IP 被封 + headless 图搜返回空 |
| ③ 抓 1688 采购价/重量 | 服务器 HTTP（`fetchOffer`） | ❌ **不行** | 服务器 IP 被封（`IP_BAN`） |
| ④ 算定价（选渠道/运费/利润） | 服务器 `PricingService.calc` | ✅ **本来就在服务器跑** | 无（纯计算） |
| ⑤ 保存定价记录 | 服务器 `createRecord` | ✅ **本来就在服务器跑** | 无（纯 DB） |

**所以真正卡住的只有 ②③ 两步**——它们都需要「出网访问 1688」。④⑤ 早就在服务器完成了，无需改造。

## 四、推荐方案 A：云控本机浏览器（详细设计）

### 4.1 架构

```
┌─────────────── 云服务器（ozon.qinxianty.com）───────────────┐
│                                                              │
│  前端工作台                    NestJS 后端                    │
│  ┌──────────┐   POST /agent/tasks   ┌──────────────────┐     │
│  │ 点「自动 │ ────────────────────▶ │ AgentTaskService │     │
│  │  核价」  │                       │  (任务表/队列)    │     │
│  │          │ ◀── GET /agent/tasks  │                  │     │
│  │          │      /poll（长轮询）  └────────┬─────────┘     │
│  │          │                                │ 派发           │
│  │          │ ◀── 结果：候选/价格 ───────────┤               │
│  └──────────┘                                │               │
│        │                          ┌──────────▼─────────┐     │
│        │  选同款（可自动）         │ PricingService.calc │     │
│        └─────────────────────────▶│ createRecord        │     │
│                                   └────────────────────┘     │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTPS（daemon 主动外连，服务器无需连入内网）
                           │ ① 拉取待办任务  ② 回传结果
┌──────────────────────────▼───────────────────────────────────┐
│ 用户本机（家庭宽带出口）                                       │
│   ┌────────────────┐   CDP 9222   ┌──────────────────────┐    │
│   │ agent daemon   │ ───────────▶ │ 真实 GUI Chrome      │    │
│   │ (node 常驻)    │              │ ~/chrome-debug-profile│   │
│   │                │              │ 含 1688 登录态        │    │
│   └────────────────┘              └──────────────────────┘    │
│        ① 下载商品图到本机临时文件                              │
│        ② 驱动图搜 → 解析候选                                   │
│        ③ 打开 offer 页 → DOM 抓价/重量/包装                    │
└───────────────────────────────────────────────────────────────┘
```

**关键点：daemon 主动外连服务器**（因为用户机器在 NAT 后，服务器连不进来）。用**长轮询**即可，无需 WebSocket：

- 不新增 WebSocket 网关、不改 nginx（站点是 http，`ws://` 还要额外配置）；
- 图搜本身要 20–40 秒，2 秒轮询延迟完全无感；
- 实现简单、断线重连成本低。

（后续若要实时推送再升级为 WebSocket，架构不变。）

### 4.2 模块与文件

| 位置 | 新增/改动 | 说明 |
|---|---|---|
| `backend/src/modules/agent/` | 改 `agent.service.ts` | 新增 `createTask` / `pollTasks` / `submitResult`；原 `findCandidates` 改为「派任务 + 等结果」 |
| `backend/prisma/schema.prisma` | 新增 `AgentTask` | `id / type / status / payload(JSON) / result(JSON) / userId / storeId / workerId / createdAt / updatedAt` |
| `scripts/browser-agent/src/daemon.mjs` | **新增** | 本机常驻进程：鉴权 → 拉任务 → 执行 → 回传 |
| `scripts/browser-agent/src/tasks/find1688.mjs` | 改 | 抽出 `imageSearch(page, imgPath)` / `fetchOfferByDom(page, url)`，供 daemon 复用 |
| `frontend/src/app/pricing/Workbench.tsx` | 改 | 卡片改为「提交任务 → 轮询状态 → 展示候选 → 选同款落库」 |
| `scripts/pack-agent.sh` + `/guide` 下载 | 新增（可选） | 把 daemon 打包给用户下载，避免用户手动配 node |

### 4.3 任务协议（REST，鉴权沿用现有 JWT）

```
POST /agent/tasks            body:{type:'image_search', sku}      → 建任务，返回 taskId
GET  /agent/tasks/poll       ?workerId=xxx                        → 取一个 PENDING 任务（长轮询 20s）
POST /agent/tasks/:id/result body:{ok, data|error}                → daemon 回传结果
GET  /agent/tasks/:id                                             → 前端轮询状态
POST /agent/tasks/:id/choose body:{offerUrl, sellPrice?}          → 选同款 → 服务器算价落库
```

任务类型：
- `image_search`：`{sku}` → 结果 `{candidates:[{offerId,title,price,shop,img,url}]}`
- `fetch_offer`：`{url}` → 结果 `{price, title, weightG, lengthCm, widthCm, heightCm}`（**替代被封的服务器 `fetchOffer`**）
- 后续可扩展 `batch_price`（批量核价）

### 4.4 一次全自动核价的时序

1. 用户在线上工作台填 SKU → 点「自动核价」
2. 服务器：取商品主图 URL → 建 `image_search` 任务（status=PENDING）
3. 本机 daemon 轮询拿到任务：
   - `GET /pricing/sourcing/image-proxy?url=<ozon 图>` 下载图片 → 写本机 `/tmp/xxx.jpg`
     （**必须下载到本机**：CDP `uploadFile` 传的是本机路径，这也顺带解决了之前"服务器路径在本机不存在"的问题）
   - 驱动本机 Chrome 打开 1688 图搜 → `uploadFile` → **点「搜索图片」** → 等待 → 用 `[data-renderkey]` 解析候选
   - 回传候选（含自建的 `detail.1688.com/offer/{offerId}.html` 链接）
4. **选同款**（两种模式，可配置）：
   - `auto`：按「标题关键词重合度 + 价格合理性 + 店铺回头率」打分取 Top1；置信度低于阈值时才回退人工
   - `manual`：候选卡片展示在网页上，用户点选（当前行为）
5. 服务器派 `fetch_offer` 任务 → daemon 打开 offer 页 → DOM 抓价/重量/包装 → 回传
   （**这一步不能走服务器 HTTP，服务器 IP 被封**）
6. 服务器：`PricingService.calc` 算渠道/运费/利润 → `createRecord` 落库
7. 前端展示定价结果

### 4.5 daemon 鉴权（免手工配置）

daemon 启动时用 CDP 连本机 Chrome，遍历标签页找 `ozon.qinxianty.com`，直接读 `localStorage.ds_token`
→ 用户只要在那台机器登录过 ds 就行，不用复制粘贴 token。
（退化路径：环境变量 `DS_TOKEN` 手工指定。）

### 4.6 多用户 / 归属

- 任务带 `userId`+`storeId`，只派给**同一用户**的 daemon（超管可看到在线 worker 列表并选择）
- daemon 心跳：每次轮询即心跳，服务器记录 `workerId → {userId, lastSeen}`，超过 60s 视为离线
- 离线时前端明确提示：**「本机 agent 未运行，无法执行 1688 任务」**，而不是报 code 1

### 4.7 失败与降级

| 情况 | 处理 |
|---|---|
| 1688 未登录 / 触发滑块 | daemon 回传 `{ok:false, error:'需要人工处理验证码', screenshot:base64}` → 前端展示截图 + 提示去本机浏览器处理 |
| 图搜 0 结果 | 回传空候选，前端降级为「手工贴 offer 链接」（走 daemon 的 `fetch_offer`） |
| daemon 离线 | 任务超时（120s）置 FAILED，提示启动 daemon |
| 任务并发 | 单 daemon 串行执行，任务排队；批量核价时每单之间随机 3–8s 间隔降低风控概率 |

## 五、长期方案 D：1688 官方开放平台 API（2026-10-09 补充申请路径）

### 5.1 结论：官方确实有「以图搜货」，且正好匹配我们的场景

- **能力页**：[图搜分销商品](https://open.1688.com/ability/detail?key=1610419169653)
  - 传入图片 URL + 页号 → 返回 1688 商品池中的相似商品列表（商品 id、标题、价格、城市、库存、起批量）
  - 支持按价格/销量排序、价格区间筛选、分页
  - 拿到 `offerId` 后调 **`alibaba.cpsMedia.productInfo`** 取商品详情（价格、规格等）→ 即官方版"抓价"
  - ⚠️ 该能力**需先订购《社交电商采购对接解决方案》**，否则查不到商品详情
  - ⚠️ 搜索范围是**分销/跨境商品池**（不是 1688 全站），召回范围与网页图搜不完全一致，需实测比对
- **跨境电商方案**（与本项目场景最匹配）：https://open.1688.com/solution/solutionDetail.htm?solutionKey=1697014160788
  面向在跨境电商平台开店的 1688 采购商，支持智能选款、一键铺货、自动下单、批量支付、订单同步
- 网上流传的 `1688.item_search_img` / `alibaba.product.image.search` / `alibaba.ai.vision.product.search`
  多来自第三方 API 中间商博客，**接口名与网关地址请以官方能力页为准**，不要直接照抄

### 5.2 申请入口与步骤

| 步骤 | 位置 | 说明 |
|---|---|---|
| 1. 账号与实名 | 用 1688/支付宝账号登录 [open.1688.com](https://open.1688.com) | 账号须先完成实名认证（支付宝实名认证） |
| 2. 入驻开发者 | 登录后右上角 **「控制中心」** → https://open.1688.com/console （首次登录弹出入驻页）<br>流程文档：https://open.1688.com/doc/guide.htm | 企业开发者：营业执照 + 法人信息 + **绑定企业实名认证的支付宝**；<br>个人开发者：身份证扫描件。**审核 1–3 个工作日** |
| 3. 创建应用 | 控制台 → 应用管理 → 创建应用 | 选 **「自用型应用」**（仅供自己公司内部使用）→ **无需 ISV 保证金、审核更快**；<br>若做成对外售卖的 SaaS 才选「ISV 第三方应用」（需保证金 + 更长审核）<br>创建后得到 **AppKey / AppSecret** |
| 4. 申请 API 权限 | 应用 → 权限/能力 → 申请「图搜分销商品」等 | 用途描述如实填写（例：跨境选品核价，按图找同款货源），直接影响审批通过率 |
| 5. 安全配置 | 应用后台 | **IP 白名单：填服务器公网 IP `114.132.99.141`**（不配会 403）<br>OAuth 回调域名须为已备案域名，不支持 localhost/IP |

### 5.3 关键提醒

- **个人也能注册**，但权限受限：只能调商品查询类接口，**交易下单类接口（createOrder）必须企业/个体工商户资质**。我们只需"图搜 + 查详情/价格"，个人资质大概率够用，但审批时以实际结果为准。
- **API 通道与网页风控是两套**：服务器机房 IP 被 1688 **网页**拉黑（`cloud_ip_bl`），但开放平台 API 走授权通道 + IP 白名单，**不受该封禁影响** —— 这正是方案 D 能"纯服务器跑"的原因。
- 网关与签名（以官方为准）：`https://gw.open.1688.com/openapi/router/rest`，MD5 首尾包裹签名，参数 ASCII 升序排序。
- 有调用配额与 QPS 限制（第三方资料称 QPS 3–10），批量核价需做限速与重试。

### 5.4 建议

**并行推进**：现在就提交开发者入驻（审核要 1–3 个工作日），同时 A 方案先落地解近渴；
等 API 权限下来后，把「图搜 + 抓价」从 daemon 切换为官方 API，daemon 即可下线，实现真正的服务器无人值守。

## 七、风险与待确认

1. **需用户机器常驻一个进程**：这是方案 A 的硬前提。若要求"服务器 7×24 无人值守且不依赖任何人电脑"，只能走 C（住宅代理）或 D（官方 API）。
2. **1688 风控**：即便在本机，高频图搜仍可能触发滑块 → 需要限速（P2 的随机间隔）+ 失败降级为人工。
3. **图搜是否必须登录**：现有实现假定需要登录态；若不需要可简化（待验证）。
4. **算价参数**：尺寸在无 1688 数据时用 20×20×20 兜底，自动化后要注意别把兜底值当真实值入库（现有 `weightSource` 字段已区分，需沿用）。
5. **线上/本地库独立**：自动化落库到线上库，本机 ds 的数据不同步，需明确以线上为准。

## 八、与现有「产品边界」的关系

现有约定是「**不做自动去 1688 抓取**」（2026-10-03 运营决定，因风控极严）。
方案 A **不违背**该约定的实质——它不改变"由真实浏览器、真实登录态、人工级操作节奏完成 1688 交互"这一事实，只是把触发方式从"人点浏览器"变成"人点网页按钮"。
唯一需运营确认的是：**是否允许「自动选同款（Top1）」**，即跳过人工挑选这一步。建议 P1 先保留人工挑选，P2 再开自动。
