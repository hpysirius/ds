## 22:40 详情页采集「录入一条商品」修复（插件 v1.5.0 + 后端改造）
- 现象：用户在 Ozon 商品详情页点「采集当前商品页」，库里没有该商品时**录入不进去**。
- 根因：后端 persistProbe() 开头 `if (!product) return 商品不存在` —— 详情页上报走的是同一条路，
  只更新不新建。列表页上报（ingestProductList）能新建，所以只有"手动录单个商品"这条路径坏了。
- 后端改造（sourcing.service.ts）：
  - persistProbe 增加 opts.create；商品不存在时按需 create，返回值带 created 标记
  - 新建后若最终没读到任何字段，把空壳记录 delete 掉（不留脏数据）
  - 新增写 productUrl（取 best.productUrl || best.url，此前详情页采集从不落 productUrl）
  - ingestFromExtension 传 { create: true }（浏览器自动补详情 enrichProductInfo 仍严格只更新）
- 插件改造：
  - collectProduct 输出 productUrl（优先 og:url → canonical → location.href）
  - collectActiveTab：先用 probeReady 轮询等待（最多 12s），撞挑战页直接报"请先过验证"；
    第三方浮层 pluginCard 渲染慢，首采没读到则 sleep 2.5s 再采一次
  - popup 采集后弹结果：新建/更新 + 写入字段数 + 字段名；失败显示后端给的 reason
  - manifest 升到 1.5.0
- 实测：本地与服务器各跑一遍详情页上报 → 均返回 created:true（含 productUrl/soldCount/sizeWeightG/createDays），
  测试数据已用新的删除接口清理干净。已 ./deploy.sh 部署到服务器。
- 教训：Ozon 详情页 curl 直连会被 307（反爬），本地无法用 HTTP 验证，只能靠插件在真实浏览器里取。
