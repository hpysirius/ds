## 01:00 商品列表「名称错误 + 大部分字段缺失」排查与修复（插件 v1.6.2）

### 现象
用户用插件采集 Ozon 类目+搜索页（袜子 / 7500），商品库里：
- 「商品」列显示的**不是商品名**，而是促销标签/价格串；
- 类目、品牌、月销、加购率、退货率、评论、广告占比、上架天、发货 几乎全是 `--`。

### 真因（查库 + 读源码得出，三条互相独立）
1. **币种符号是 `¥` 不是 `₽`**。用户浏览器里 Ozon 价格显示成 `33,19 ¥180,93 ¥−81%`（中文界面 + 符号被本地化/替换）。
   插件老代码只认 `₽`：所以 ① 价格正则全不匹配 → `price` 全丢；② 标题过滤条件 `t.indexOf('₽') < 0` 失手 →
   **价格串被当成商品名入库**。库里 343 条中 104 条短标题含 `¥`。数值仍是卢布量级（与 URL 的 `currency_price=20;618` 区间吻合），所以**不做换算**、只把符号留档。
2. **促销/库存标签是中文**（`还剩3件新品` / `还剩1件大促销`）。老 LABEL/STOCK 正则只写了俄语，中文界面下全部失手 →
   12 条以「还剩」开头的标题入库。
3. **第三方选品插件（中实跨境ERP / 闪电采集）浮层文本被当标题**，83 条形如
   `闪电采集选品标签：类目：暂无数据rFBS佣金：…月销量：暂无数据…跟卖最低价：23,15 ¥`。
   浮层里全是「暂无数据」= 插件装了但**没有 Ozon 卖家登录态/未绑定**，这才是月销/加购率/退货率/广告占比/上架天缺失的根因（不是代码问题）。
   另注意它也把价格写成 `¥`，与 1 一致。

### 修复
**插件 `extension/ds-collector/collector-lib.js`（列表页解析重写）**
- `parsePrice()` 支持 `₽ ¥ $ €` 全部符号，返回 `{value, symbol}`；价格串「现价 划线价 折扣」取**第一处**为现价。
- `okTitle()` 硬闸：含货币符号/`%` 一律不是标题；LABEL/DATE/STOCK/REVIEW/UNIT_ONLY 全部**俄语+中文双语**；
  新增 `NOT_TITLE`（`选品标签|类目：|rFBS佣金|月销量|跟卖最低价|暂无数据`）——**文本层**兜底，不依赖 DOM class。
- 标题取值链：① 商品链接 title/aria-label ② `img[alt]` ③ class 含 `tsBody`（优先 500 号，取最长）④ 全卡取最长合格文本。
- 价格/评论/评分改为「先收集全部候选文本再挑」，不再依赖元素遍历顺序（老代码被父容器拼接文本抢先命中）。
- 评论数支持中文 `12 条评论`；修 `\w` 不匹配西里尔字母的 bug（改 `отзыв[а-яё]*`）。
- 浮层读取抽成 `readPluginCard()`，新增**全局 `[data-s2-ozon-sku]` → pluginCard 索引**（浮层不在卡片里也能按 sku 兜底）。
- `collectProduct()` 的 h1 兜底与评论正则同步加中文/浮层防护。

**插件 `background.js` / `popup.js`**：列表采集后输出**字段覆盖统计**（名称/价格/主图/评论/经营指标各多少）并显示在弹窗结果里 ——
以后「哪一列为什么是空的」一眼可见，不用再猜。

**后端 `sourcing.service.ts`**
- 新增 `isJunkTitle()`（短文本 + 促销标签/价格串特征）与 `PRICEY_TITLE_RE`；`ingestFromExtension` / `ingestProductList` 都拒收这种标题。
- `WIDGET_TITLE_RE` 补 `闪电采集`。
- **自愈**：列表重复采集时若本轮没解析出标题、而库里存的是脏标题（junk / 浮层 / 反爬）→ 直接置 `title=NULL`，
  否则脏值会永久残留（空标题不覆盖 → 脏标题赖着不走）。
- `raw` 里留档 `priceSymbol`，便于日后核对价格是否被本地化换算过。

**服务器数据清理（一次性 SQL，已执行）**：清掉 83 条浮层文本标题 + 116 条标签/价格串标题 →
清完 `标题为空 236 / 有标题 107 / 有价格 270`（总数 343）。剩 236 条空标题需靠重新采集/批量补详情回填。

  俄语界面、卡内 ERP 浮层、纯脏卡片、`¥` 价格串、浮层 class 改名等场景。
- `tsc -p tsconfig.build.json --noEmit` 通过；插件三个文件 `node --check` 通过；`./deploy.sh` 部署成功（健康检查 200/401）。

## 06:00 1688「包装信息（商品件重尺）」抓到 1×1×1 —— 占位值坑（插件 v1.6.3）

### 现象
插件抓 `https://detail.1688.com/offer/1025753259031.html`（袜子），包装信息是
`长1 宽1 高1 体积1 重量92` —— 长宽高明显是假的。

### 真因：1688 的「默认占位值」
直接 curl 该页（**这次没被风控**，200/79KB）看内联 JSON：
```
productPackInfo.fields = {
  unitWeight: 0.092,                       // kg → 92g，真实重量
  pieceWeightScale.pieceWeightScaleInfo: [ { volume:1.0, length:1.0, width:1.0, weight:92, height:1.0 } ]
}
```
→ **商家根本没填长宽高**，1688 接口照样返回 `1/1/1/1` 占位值。老代码把它当真值回填，
核价里体积重/抛重/运费全算错（1cm³）。`skuWeight` 是空对象 `{}`，也拿不到 per-sku 重量。
另：`skuMap` 里**没有 price 字段**，只有 `priceAmount:1` —— 那是「阶梯价档位数」不是价格，
老兜底会把它当 ¥1。**已删除 priceAmount 兜底**。

### 修复
**插件 `supply1688-collector.js`（重写包装部分）**
- 新增 `isPlaceholderPack(l,w,h,volume)`：三边全 ≤1 或 体积 ≤1 → 判占位；`usableDims()` 再加 >500cm 离谱值过滤。
- 包装取数链（返回 `pack.source` 便于排查）：
  `本地缓存`(上次手填) → `内联 productPackInfo`(含 `fields.unitWeight` kg 兜底重量) → `页面「商品件重尺」表格`(按表头 长/宽/高/体积/重量 对齐) → `可见文案`(包装尺寸 33*22*11 / 长24cm… / 净重0.09kg) → `规格名自带尺寸`(17*7*3)。
- 新增 `readPackTable()`：找含「商品件重尺」的最小容器 → 取 table → 按 th 表头映射列 → 取第一条可用数据行。
- 返回新增 `pack{weightG,l,w,h,volumeCm3,source,placeholder,rows}`；占位/缺失时尺寸一律 `null` + warnings 提示手填。
- `sliceAllBalanced()`：同名 key 多次出现（占位在前、真实在后）全部切出来逐个试。

**插件 `background.js` / `popup.js`**
- 新增 `dsPackCache`（chrome.storage.local，按 offerId，上限 300 条）：回填时把**手填过的长宽高**记下来，
  下次抓同一货品自动带上（1688 自己没填时这是唯一可信来源）。新增消息 `DS_SAVE_PACK`。
- `collect1688()` 用 `executeScript({func, args:[cache]})` 把缓存传进页面。
- 缺尺寸时输入框**清空并标黄**（以前会填 1 进去），弹窗显示包装来源与「缺失（1688 页面上是默认的 1×1×1）」。

**后端 `sourcing.http.ts`**：同步加 `isPlaceholderPack()` / `usablePackDims()`；pieceWeightScaleInfo 只取非占位行；
`productPackInfo.fields.unitWeight`（kg→g）兜底重量；新增返回字段 `packPlaceholder` + warning「请手动填长宽高」。
**前端 `Workbench.tsx`**：日志不再打印 `undefined×undefined`。

## 06:20 1688「区间价」商品抓不到价格 —— 阶梯价兼容（插件 v1.6.4）

### 现象
同一个货品 1025753259031：1688 页面上「选了尺码就有价格」（规格行显示 ¥3.5），但插件下拉里规格**没有价格**、成本填不出来。

### 真因：1688 两种定价方式，只写了一种
- **(a) 按规格定价**：价格在 `skuMap`/`skuMapOriginal`/`skuInfoMap` 的 `price`/`discountPrice` 里（老商品/上一个商品 5611145930 就是这种）。
- **(b) 按购买数量阶梯定价（区间价）**：`skuPriceType:"rangePrice"`，`isRangePriceSku:true` ——
  **规格列表里根本没有价格字段**（那里只有 `priceAmount`＝阶梯档位数，值为 1，不是钱！），
  价格在 `offerPriceRanges` / `currentPrices` / `skuRangePrices` 里；页面上每个规格行显示的是
  **最小起批量那一档**的价。
  实测该页：`skuRangePrices:[{price:"3.50",beginAmount:1},{price:"2.96",beginAmount:300}]`、
  `skuPriceScale:"2.96-3.50"`、`priceDisplay:"3.50"`。

老代码只认 (a)：插件 pushSku 拿不到价 → 下拉无价、成本不填；后端 `if (!priceN) continue` 把 sku 全跳过（skus=0）。

### 修复
**插件 `supply1688-collector.js`**
- 新增阶梯价解析：依次试 `offerPriceRanges` → `currentPrices` → `skuRangePrices`，产出 `priceRanges[{price,beginAmount,endAmount}]`。
- `basePrice` = **起批量最小那档**的价（= 页面规格行显示价）；`priceMin/priceMax` 从 `skuPriceScale`（或 offerMinPrice/offerMaxPrice）取。
- sku 价格兜底链：规格自带价 → `basePrice` → `priceDisplay` → 页面 ¥ 文案。**价格、尺寸现在都成了"规格自带 → 全局兜底"两层**。
- 返回新增 `basePrice / priceMin / priceMax / priceRanges / minOrderQuantity`；warnings 提示「按数量阶梯定价：≥1件 ¥3.5 / ≥300件 ¥2.96 —— 已按最小起批量填成本」。
- 规格名的 HTML 实体还原（`藏青色&gt;女款37-41码` → `藏青色>女款37-41码`）。

**插件 `popup.js`**：抓取结果里显示阶梯价一行，并注明成本按哪档填的。

**后端 `sourcing.http.ts`**：同样加 `priceRanges`/`basePrice`/`priceMin`；sku 的 `priceN` 缺失时用 `basePrice` 兜底（**不再整条跳过**，skus 从 0 → 2）；
`price` 语义明确为「核价该用的单件成本」= `basePrice ?? 最低价`（**区间价商品必须用起批价，用最低价 2.96 会低估成本、把利润算高**）；
`allPrices` 并入阶梯价档位；`decode()` 规格名实体。
