## 1688 找货源自动化：把每一步实测到可用

接着 9-19 的定价工作流，今天专攻 1688 自动化（调了十几轮，记下结论，别再走弯路）。

### 已验证可用 ✅
1. **抓 Ozon 主图**：`POST /pricing/sourcing/product-image`，打开商品页读 `meta[property="og:image"]`，
   并回写 `products.imageUrl`（插件采集的数据里根本没有图片字段）。
   泡泡机实测得到 `https://ir-20.ozonstatic.cn/s3/multimedia-1-2/c600/14562812702.jpg`。
2. **把主图塞进 1688 图搜上传框**：`POST /pricing/sourcing/prepare-search` → `uploaded: true`。
   入口是 `https://air.1688.com/kapp/1688-search/pc-image-search/?tab=imageSearch`
   （`search.1688.com/youyuan/index.htm` 会 302 过去）。
3. **点「搜索图片」**：`POST /pricing/sourcing/trigger-search` → `clicked: true`，
   搜索真的执行了（结果页 URL 带上 `imageId=...`）。用 `Input.dispatchMouseEvent` 按坐标点，
   不依赖渲染进程 JS。
4. **抓 1688 货品页**（最关键）：`POST /pricing/sourcing/offer` 实测 15 秒返回
   `{"price":18.8,"priceMax":20.8,"weightG":350,"lengthCm":14,"widthCm":11,"heightCm":30,"packSkuCount":4}`
   —— 与用户 9 月表里的 350g / 30*14*11 完全一致。

### 还不能可靠自动化 ❌
**从 1688 图搜结果页把货源列表抓回来**：那是超重 SPA，DOM 里没有 `a[href*="/offer/"]`，
Network 里也只有推荐接口。用户手动点完搜索后结果在其浏览器里可见，但脚本读不稳。
→ 折中方案：`POST /pricing/sourcing/scan-tabs` 扫描所有 1688 标签页
（offer 详情页可从 URL 直接拿到 id），前端把结果页地址回显成可点链接，货源选择交回给人。

### 踩过的坑（重要，能省很多时间）
- **新建标签页一开始是 `about:blank`，此时 `readyState` 就已经是 `complete`**。
  只等 readyState 会对着空白页抓一通、字段全 null。必须先 `location.href.includes(<id>)` 再等非 loading。
- **重页面加载约 10 秒后渲染进程会忙死不回 CDP**：等 12 秒再 `Runtime.evaluate` 必超时；
  3 秒内求值正常。所以：`Page.enable`/`DOM.enable` 一 attach 就开，
  然后每 700ms 轮询 `document.readyState`（带 4s 超时）而不是先 sleep 十几秒。
- **`DOM.*` 域命令在重页面上会挂**（`DOM.getDocument` pierce 直接超时）。
  改用纯 JS：`DataTransfer` 造 `File` 赋给 `input.files` 并派发 change，绕过 DOM 域。
- **CDP 命令一律带超时**：`Target.createTarget/attachToTarget/getTargets` 都给 8s，
  否则默认 60s 一个卡住的页面就能把接口拖死（scan-tabs 曾因此 120s 无响应）。
- `Node.EPSILON` 式四舍五入在 2.705 这种值上会向下取整（2.70 vs 表内 2.71），
  改成 `r2 = Math.round((n + 1e-9) * 100) / 100`。
- 后端/前端别用 `(cmd &)` 后台起，会话间隙会被回收；要用 run_in_background。

### 定价链路最终结果（真实数据）
1688 成本 18.8 / 350g / 14×11×30 → GUOO Economy Extra Small 运费 ¥13.21
→ 定价 ¥43（₽498.84）· 毛利 ¥2.33 · 净利 ¥2.07 · 利润率 11.02% · 运费利润比 15.68% · 加35% ¥66.15
→ 已存进定价表（记录 id=3），CSV 列头与《9月定价表》一致。

## 重大转向：甩掉浏览器，1688 全部走纯 HTTP（用户嫌浏览器链路卡、慢、不成）

### 实测出来的三条硬结论
1. **货品详情页 detail.1688.com/offer/<id>.html 是 SSR、匿名可抓**：0.6 秒返回，
   页面里内联 JSON 有 `"priceDisplay":"18.80"` 与 `pieceWeightScaleInfo`（每个 SKU 长宽高重量）。
   → 之前走浏览器要 15~60 秒，现在 0.68 秒。
2. **PC 搜索页 s.1688.com 是空壳 SPA，抓不到东西**；但**移动端 m.1688.com/offer_search/-6BE2.html?keywords=xx
   是完整 SSR**，一次返回 20 张卡片（图 `data-src`、标题、`¥x.x`、成交、城市），0.5 秒。
   **但它要求登录态**：不带 cookie 会返回一个 4.8KB 的跳 login.1688.com 页面（`x5secdata` 那段）。
3. **Ozon 商品页对服务端请求返回 307**（抓不到 og:image），所以 Ozon 主图这条还是只能浏览器/手填。

### 登录态怎么解决（关键技巧）
- 不需要解密 Chrome 的 Cookie 数据库！直接用 CDP：
  - `Storage.getCookies`（浏览器级，无参数）一次能拿到全部 1681 条 cookie ← **首选**
  - 拿不到时退到：附一个页面 target 再 `Network.getCookies({urls:[...1688 域名]})`
  - 注意 `Network.getAllCookies` 在本机返回 0 条，别用
- 只读 cookie、不渲染页面，0.15 秒同步完，存进 `pricing_settings.ali1688Cookie`，
  之后全程纯 HTTP。实测**关掉调试 Chrome 后搜款照常可用**。

### 新增
- `backend/src/modules/pricing/sourcing.http.ts`：`httpGet` / `parseSearchCards` / `parseOfferHtml`
  （`pieceWeightScaleInfo` 用括号配对切完整数组再 JSON.parse，比正则稳）
- 接口：`GET /pricing/sourcing/cookie-status`、`POST /pricing/sourcing/sync-cookie`、
  `POST /pricing/sourcing/cookie`（手动粘贴）、`POST /pricing/sourcing/search-keyword`
- `fetchOffer()` 改成 **HTTP 优先**，浏览器版降级为 `fetchOfferByBrowser()`（只有 HTTP 拿不到才用）
- 前端工作台主按钮变成「1688 搜同款」（关键词默认取商品库的中文末级类目，如「儿童泡泡机」），
  浏览器那套（以图搜款/读取结果）退到次要位置
- 多 SKU 时取尺寸：优先挑「长宽高齐全」的那条拿尺寸，重量单独找第一条有的

### 全链路耗时
商品库带关键词 0.14s → 搜同款 0.80s → 抓价格+包装 0.89s ≈ **1.8 秒**（原来几分钟还不一定成）

## 图片搜索能不能纯 HTTP？（结论 + 风控坑）

### 试过但走不通的路
- `air.1688.com/kapp/1688-search/pc-image-search/?imageId=…`：HTML 只有 6.2KB 空壳，
  结果是前端 JS 拉的；用 CDP 录网络（含 autoAttach 子框架、放开所有请求类型）
  也只看到 `mtop.relationrecommend…recommend`，**抓不到图搜结果接口**。
- `m.1688.com/offer_search/-6BE2.html?imageId=…`、`m.1688.com/image_search.html?imageId=…`、
  `s.1688.com/youyuan/index.htm?tab=imageSearch&imageId=…` 全部返回空壳或 login。
- 上传接口也藏在 app 内部（注入 File 后录不到 upload 请求）。
→ 结论：**1688 图搜没有可直接调的公开 HTTP 接口**，要纯 HTTP 只能走开放平台 appKey（未接入）。

### 但有个大坑（重要）
短时间连续请求后，`m.1688.com` 搜索会把出口 IP 拉黑，返回**滑块惩罚页**
（URL 里 `_____tmd_____/punish?x5secdata=…`）。实测：
- **受影响**：关键词搜索接口
- **不受影响**：`detail.1688.com/offer/<id>.html` 详情抓取（风控期间仍 0.68 秒拿到价格+包装）
→ 所以设计成：搜索只是"找链接"的手段（有节流 1.5s/次 + 5 分钟缓存 + 命中风控后 3 分钟冷却），
  拿到链接后的价格/包装永远是纯 HTTP 秒级，稳定。

### 最终三条找货源路径（按推荐度）
1. **关键词搜同款**（纯 HTTP，20 条/0.5s，可能被风控）
2. **以图搜款**（更准）：调试 Chrome 打开图搜页 → 系统自动注入商品主图 + 自动点「搜索图片」
   → 回系统点「读取浏览器里的结果」，scanTabs 收链接后**用 HTTP 补全标题/价格**（已验证）
3. **直接粘贴 1688 链接** → HTTP 抓详情（最稳，永远可用）

### cookie 教学（用户要的）
Chrome 登录 1688 → F12 → Network → 刷新 → 点第一条 www.1688.com 请求 →
Request Headers → Cookie → 复制值 → 粘到工作台「粘贴 Cookie」弹窗（或 POST /pricing/sourcing/cookie）。
也可以点「同步 1688 登录态」让系统从调试 Chrome 里读（CDP `Storage.getCookies`，0.15 秒）。

- `"…$ROOT）"` 这种**变量后面紧跟中文全角字符**会让 bash 把多字节字节当成变量名的一部分，

1. `BrowserService.ensure()`：**只有首次要复制配置（profileReady=false）时才要求退出 Chrome**。

## 采集"卡卡的、很难成功"的排查与加固

### 关键实测结论（都验证过）
1. **Ozon 榜单页首次加载要跑约 90 秒重度 JS**：这期间渲染进程**完全不回 CDP**（所有求值超时、
   连 `Page.enable` 都超时），之后才 `readyState=complete` 并注入 16 张 `data-s2-card-data-json` 卡片。
   → 原来代码用 `sleep(15000)` 猜加载时间，必然踩雷。
2. 标签页不在最前时 Chrome 会节流/冻结后台渲染进程 → 必须 `Page.bringToFront`，
   启动参数也补了 `--disable-background-timer-throttling --disable-backgrounding-occluded-windows
   --disable-renderer-backgrounding --disable-features=CalculateNativeWinOcclusion`。

## 补图彻底修好（53/53 全有图）+ 采集防丢图

### 补图失败的最终根因：多行模板字面量 → CDP SyntaxError
- `ev(\`(() => { ... })()\`)` 这种多行模板字面量发给 Chrome `Runtime.evaluate` 时，
  **Chrome 报 `SyntaxError: Unexpected end of input`**（表达式在 Node 里语法检查 OK，但 Chrome 不接受）
- **修法**：压成单行字符串（普通双引号字符串，不用模板字面量），立刻就能用了
- 实测：单行表达式 14.8 秒拿到图（页面加载要几秒 + 轮询）

### 其他修了的点（排查过程中发现）
1. **withPage 的 rawEval 超时太短**（6s → 12s）：Ozon 重页面单次求值要 7-8 秒
2. **readyState 循环没 try/catch**：单次超时会直接把整个 withPage 打挂
3. **URL 规范化**：分享/带跟踪参数的链接（`?_bctx=...&at=...`）会被 Ozon 送进反爬校验页
   → 规范成 `https://www.ozon.ru/product/<id>/`
4. **标签用完即关**：`Target.closeTarget` in finally（标签堆积会把渲染进程池占满）
5. **bringToFront**：后台标签会被 Chrome 冻结

### 采集防丢图（persist）
- `isRealImage()` 只认 `http(s)` + ozon/1688/alicdn 域名的图，拒绝 `data:`/`chrome-extension:`/`blob:`
- `incomingImage = isRealImage(imageUrl) ? imageUrl : isRealImage(__image) ? __image : ...`
- upsert 的 update 分支：`imageUrl: incomingImage ? incomingImage : undefined`
  → Prisma 里 `undefined` = 不更新这列，**不会用 null 覆盖已有好图**
- GRAB_JS 里加了 DOM 兜底：从卡片 `img.srcset`/`data-src`/`src` 取图，写进 `d.__image`
