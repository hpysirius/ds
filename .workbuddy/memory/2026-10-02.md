
## 07:56 新增「岗位角色」层：角色分配页面权限，员工分配角色
- 需求：在账号之外再加一层「角色」，页面权限挂在角色上，员工只选角色即可控权。
- 数据模型（prisma/schema.prisma）：
  - 新增 `Role` 模型：id / name / code(唯一) / permissions(JSON 文本) / remark / 时间戳，映射到表 `roles`。
  - `User` 新增 `roleId Int?` + 关联字段 **`roleRef Role?`**（字段名不能叫 role，User.role 已是角色字符串列），`onDelete: SetNull`，并加 `@@index([roleId])`。
- 后端：
  - 新模块 `src/modules/roles`（service/controller/dto/module），接口 GET·POST /roles、PATCH·DELETE /roles/:id，`@Roles(...USER_MANAGE_ROLES)`。
  - `common/constants/permissions.ts` 新增权限 key `system_roles`，并新增 `resolvePermissions(user)`：**超管全量 > 角色权限 > 个人 permissions 兜底**。
  - users：DTO 支持 `roleId`（传 null 可取消角色）；service 的 toDto 输出解析后的**生效权限** + roleId/roleName；新增 `findByIdWithRole`（登录/profile/jwt 必须用它才能带上 roleRef 解析角色权限）；`findByUsername` 也 include roleRef。
  - jwt.strategy / auth.service.login 改用 `resolvePermissions`。
- 前端：
  - 新增 `/system/roles` 页面：角色 CRUD + 权限树（antd Tree，分组 key 前缀 `g:`，onCheck 过滤掉分组）。
  - `/system/users` 增加「岗位角色」列与角色下拉（allowClear）；选了角色则权限树只读（disabled）并提示去角色管理改；未选角色仍可直接勾选（兜底）。原「角色」列改名为「系统角色」以免混淆。
  - AppShell 系统管理菜单加「角色管理」；`lib/permissions.ts` 加 system_roles，admin 自动补 system_users+system_roles。
- 验证（本地+线上）：建角色 → 员工挂角色 → 登录拿到角色权限；改角色权限后员工重新登录生效；删除角色后员工 roleId 置空、权限回落；重名 code 409；员工访问 /roles、/users 均 403；`_count` 已从角色响应里剔除。
- 坑：Prisma 关联字段名不能与已有标量列 `role` 同名，必须用 `roleRef`；改 schema 后必跑 `npx prisma generate` 再 tsc。

## 11:05 修复「采集规则勾了评论0-1，采集出来却都是有评论的」——插件规则只是打标，新增「过滤模式」
- 用户反馈（浏览器插件 `extension/ds-collector`）：在「采集规则」里设了「评论 0 或 0-1」，采集出来的商品却都带评论。
- 根因（非小 bug，是设计缺陷）：`rules-lib.js` 的规则只做**打标（tag）**；`background.js` 的 `collectListPage` / `collectActiveTab` 都是**全量采集**，只在末尾调 `tagItem()` 给命中的商品贴标签，**从不过滤/丢弃**未命中的商品。所以「评论0-1」只让 0-1 的商品多个标签，带评论的照样入库。`popup.js`/`rules.html` 文案也写明是「自动打标签」。
- 修复（新增真正能过滤的能力，默认关、向后兼容）：
  - `rules-lib.js`：新增 `ruleHasConstraints(rule)`（规则是否带实际条件——品牌/发货/任一范围条件；无条件规则命中全部、不能当过滤器）与 `passesFilter(item, rules)`（命中任意带条件启用规则即通过；一条带条件规则都没有则全部放行，避免把商品全滤光）。
  - `background.js`：新增 `FILTER_KEY='ds_filter_mode'` + `getFilterMode()`；`collectListPage` 在入库前按 `passesFilter` 过滤未命中商品（记日志、返回值带 `filtered` 计数）；`collectActiveTab` 单页采集也遵守（未命中则跳过不上报，返回 `{ok:false,reason}`）。
  - `popup.html`/`popup.js`：弹窗加「过滤模式（只采集命中规则的商品）」复选框，读写 `chrome.storage.local.ds_filter_mode`。
  - `rules.html`：新增说明框区分「打标签」vs「过滤模式」；`manifest.json` 版本 1.6.4 → 1.6.5。
- 验证：`rules-lib` 用 node 跑 15 条单测全 PASS（评论0-1 命中 rc=0/1、过滤 rc≥2 与 rc=null；零评论规则、无条件放行、停用不计入等）；改后 4 个脚本 `node --check` 语法全过（**踩坑：`await` 不能写在 `Array.filter` 的非 async 回调里，必须把 `getRules()` 提到外面**）。
- 已知局限（已写进规则页文案）：过滤依赖列表卡片能读到评论数；读不到的字段判为「不命中」会被过滤掉（宁缺毋滥）。若列表页不暴露评论数，可用详情页「采集当前商品页」配合过滤模式，或走后端「筛选」模块（screening 有评论数规则）。
