# 2026-09-22 补信息抓不到类目/价格 的排查与修复（承接 09-21）

## 类目一直抓不到的根因（实测确认）
- Ozon 商品页的类目面包屑挂在 **`[data-widget="breadCrumbs"]`**（驼峰、大写 C）。我原先写的选择器是
  `[data-widget*="breadcrumb"]`（全小写）→ 永远匹配不上（"breadCrumbs" 里的 "Crumb" 是大写 C）。
  实测：`[data-widget*="bread"]` 命中 1 个，其 innerText = "Дом и сад\nТовары для праздников\n…"，4 个 `a`。
- 而且面包屑是 **JS 延迟渲染**的：实测导航后 0ms 时 `bodyLen=0`、面包屑为空，3~5 秒（有时十几秒）才出现。
  只等 `location.href` 跳转就开抓，只能拿到服务端渲染的 meta（title / og:image / price），类目和评论永远读不到。
- 修复：新增 `WAIT_READY_JS`（等 `[data-widget*="bread"] a` / `[class*="breadcrumb"] a` 出现，上限 8 秒、间隔 500ms，
  等不到也继续，不会像旧版那样死等 60 秒）；面包屑选择器改为同时覆盖 `bread`/`Bread`/`breadcrumb`/`Breadcrumb`。

## 价格
- 价格来自 JSON-LD 的 `offers.price`（实测 389、1216、266 都能拿到）。另加了兜底：
  `product:price:amount` meta → 正文正则 `(\d[\d\s\u00a0]*)[\s\u00a0]*₽`。
- 实测之前价格为空的商品（5733070101）补信息后 price=266.00，接口返回 `{"ok":true,"fields":["title","categoryPath","price","imageUrl","reviewsCount"]}`，**耗时 9.3 秒**（旧版 60 秒+）。
- 商品列表页原先**根本没有价格列**，已新增「价格」列（`dataIndex:'price'`，右对齐、可排序、渲染成 `1 216 ₽`），
  `scroll.x` 1700→1800。后端 `products.service.ts` 的 `SORTABLE` 本来就含 price，接口也一直返回 price。

## 其它顺带修的
- 评论数正则补上不换行空格：Ozon 数字里用 `\u00a0`，原 `[\d\s]*` 匹配不到 → 改为 `[\d\s\u00a0]*`。
  另：正文含「Нет отзывов」时直接置 `reviewsCount=0`（区分"没有评论"和"没抓到"）。
- `withPage` 里的 1688 登录检测改为只试 1 次（`ev(expr, 1)`）：它是给 1688 用的，Ozon 页面恒为 false，
  但在重页面上可能超时，默认重试 3 次 × 12 秒 = 最坏白卡 36 秒。
- 批量补信息的筛选条件再调整：只按**稳定能补到**的字段挑（categoryPath / imageUrl / price / reviewsCount），
  brand、rating 只"顺带补"不参与筛选 —— 这批白牌商品 Ozon 上 brand 是空串、正文「Нет отзывов」，
  若按 brand 筛选会被反复挑中、永远补不完。

## 现状与说明
- 全表 356 条：有类目 85、有价格 90、有主图 96、有评论数 356、有品牌 84（品牌基本是白牌货，Ozon 上本来就没有）。
- **重要**：月销 / 加购率 / 退货率 / 广告占比 / 上架天 是 ERP 插件专属数据，公开页面没有，插件卸载后不会再有。
- 单条约 10 秒，批量按钮每次补 3 条 × 最多 8 轮 = 点一次约 24 条；356 条全补完需多点几次（总时长约 1 小时）。

## 排查手法（可复用）
- **验证注入到浏览器的 JS 是否正确**：从 TS 源码正则抽出模板字面量内容后，必须 `eval('`'+raw+'`')` 真正求值再统计
  反斜杠个数（只做字符串截取会把 `\\s` 误判成双反斜杠）。可用 `new Function(js)` 查语法。
- **不想起后端也能验证抓取逻辑**：用 `/tmp/verify_probe.js` 直连已运行的调试 Chrome（127.0.0.1:9222），
  `Target.createTarget` + `attachToTarget` + `Runtime.evaluate`，分时段采样看内容何时渲染出来。
  Node 22 自带全局 `WebSocket`，不用装 ws 包。
- Ozon 挡 curl（307 循环），拿不到 HTML，只能靠调试浏览器；mysql 客户端本机没装，查库用
  `docker exec playlish-mysql mysql -uroot -p"$PW" ds --default-character-set=utf8mb4 -e "..."`（不加 utf8mb4 会把西里尔文显示成问号）。
- 表名是 `products`（Prisma @@map），不是 `Product`。
