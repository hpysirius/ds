## 21:25 追加：浏览器接管功能在服务器上做优雅降级

- 现象：在 /collect 点「启动/检查浏览器」报错 `rsync ... change_dir "/root/Library/Application Support/Google/Chrome" failed`。根因：`BrowserService` 是 macOS 桌面专属——复制本机 Chrome 配置 + `open` 启动带调试端口的 Chrome（依赖 GUI + 已登录插件）。服务器无 GUI/Chrome，该目录不存在 → 崩。
- 修复：在 `backend/src/modules/browser/browser.service.ts` 加 `isSupported` getter（`process.platform === 'darwin'`），`status()` 与 `ensure()` 在非 macOS 时直接返回友好中文提示（ok:false / supported:false），不再执行 rsync。`frontend/src/app/collect/page.tsx` 加 Alert 横幅：`browser?.supported === false` 时显示“浏览器接管功能当前不可用”。
- 验证：`GET /api/browser/status` 与 `POST /api/browser/start` 经 80 端口均返回清晰提示、后端错误日志干净。
- 结论：采集/浏览器接管**必须在用户 Mac 本机运行**（要的是装了插件、登了号的 Chrome）；服务器仅跑 API + Web + 数据。此功能非部署缺陷，是架构限制。
- 关键代码事实：`BrowserService.portUp()` 连的是 `127.0.0.1:9222`（host 写死回环），`chromeBin` 写死 `/Applications/Google Chrome.app/...`。即采集后端必须与 Chrome 同机（= Mac）。服务器无 GUI/Chrome → 端口起不来 → 采集任务报「调试端口未就绪」。
- **把采集数据送进服务器库的推荐做法**：Mac 本地跑后端+Chrome 采集，开 SSH 隧道 `ssh -L 3306:127.0.0.1:3306 root@114.132.99.141`，Mac 后端 DATABASE_URL 改 `mysql://root:<pw>@127.0.0.1:3306/ds`（服务器 MySQL 已 bind 127.0.0.1，只能经隧道访问）。采集即写服务器库，前端立即可见。

## 21:55 追加：本地一键部署脚本 deploy.sh（tar 直推，已实测跑通）

- 因服务器访问 GitHub 不稳（clone 断流），最终放弃 git clone 方案，改用**本地 tar 直推**：`deploy.sh` 在项目根目录，本地 `./deploy.sh` 即完成「打包源码 → SSH 直传 /root/ds → 重建 env/ecosystem → 构建前后端 → prisma db push（幂等）→ pm2 重启 → 健康检查」。
- 关键设计（踩坑后定型）：
  - tar 与 ssh 分两条管道：`tar -czf - ... | ssh 'rm -rf /root/ds && mkdir -p ... && tar -xzf - -C /root/ds'`，**不在同一 heredoc** 内，避免二进制流被当脚本。
  - 远端 env/构建/pm2 各用一个 `ssh ... "bash -s" <<'EOF'`（**EOF 必须加引号**，否则本地 set 会展开 body 里 `$i` 等变量报 unbound）。
  - tar 排除：`node_modules .git .next dist run *.sql .env .env.local */.env */.env.local .workbuddy deploy.sh`。
  - 服务器专属文件（ecosystem.config.js、backend/.env、frontend/.env.local）脚本内自动重建；DB 密码读 `/root/.ds_db_root.txt`；JWT 持久化到 `/root/.ds_jwt.txt`（首次随机生成，重部署复用，登录态不失效）。
  - 前端 `NEXT_PUBLIC_API_URL` 写死 `http://114.132.99.141/api`（80 端口 nginx 反代）。
- 实测结果：TRANSFER_DONE（638 文件）、前后端构建成功、pm2 双 online、健康检查 `frontend / -> 200`、`/api/auth/profile -> 401`。
- 用法：本地改完代码 → `./deploy.sh`（无需手动 push GitHub，脚本直接传本地工作区）。之后重部署即跑此脚本。
