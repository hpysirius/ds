## 01:00 商品库删除功能（前后端 + 已部署服务器）
- 后端 products 模块：原本只有 `DELETE /products/:id`（前端没按钮，且无存在性校验）。
  - service：抽出 buildWhere(q) 供列表查询与「按筛选删除」共用；remove() 加存在性校验返回 {ok,id,sku}；
    新增 removeMany({ids?,filter?})：ids 优先，否则按 filter 删，两者都空 → 400 拒绝（防误清库）。
  - controller：新增 `POST /products/bulk-delete`（用 POST 不用 DELETE：DELETE 带 body 易被 nginx 丢）。
  - product_metrics 是 onDelete: Cascade，删除商品会连带删指标历史，无需手动清理。
- 前端 products/page.tsx：表格加 rowSelection + 顶部「删除所选(N)」「删除筛选结果(N)」两个危险按钮（Modal.confirm 二次确认）；
  每行操作列加「删除」（Popconfirm）。api.ts 拦截器现在把 err.response 挂到 Error 上，页面可识别 401 提示"请先登录"。
- 鉴权：删除接口是 @ApiBearerAuth，前端从 localStorage['ds_token'] 带 Bearer（登录接口返回字段是 accessToken，不是 access_token —— 易踩坑）。
- 本地实测：单删/批量删/按筛选删/空请求拒绝 全通过；已用 ./deploy.sh 部署到服务器（前端构建 + pm2 重启），
  服务器 /products 页已含删除按钮，bulk-delete 空请求 400、未登录 401，均符合预期。
